# 觀眾視角故事設計原則
# Audience-First Story Design Principles
**版本：** 1.0 | **建立日期：** 2026-07-15
**觸發來源：** IP 老師對 Legacy FootCare 鞋墊合作片口播稿的四點診斷（2026-07-15）

---

## 一、這個框架解決什麼問題

現有 `story_reel_structure.md` 建立了故事型 Reel 的十段落結構，但沒有系統化定義「觀眾視角」的設計原則——即如何確保每一句口播都是「觀眾想聽的」，而不是「你想說的」。

IP 老師的四點診斷揭示了一個根本問題：**「你用自己的角度講故，而唔係用觀眾的角度。」** 這個問題在任何類型的 Reel 都會出現，不只是故事型片。

本框架提取老師診斷背後的底層邏輯，建立一套可重複應用的「觀眾視角設計原則」。

---

## 二、老師診斷的底層邏輯分析

### 老師的核心哲學（推斷的 Prompt 結構）

老師的診斷框架可以用一句話概括：

> **「觀眾睇片，第一秒問嘅係『呢樣嘢關我咩事？』——你的每一句話，都必須先回答這個問題，才能繼續說下去。」**

這個哲學背後有三個層次：

| 層次 | 核心問題 | 設計原則 |
|------|---------|---------|
| **第一層：Hook** | 「這個人是誰？關我咩事？」 | 先釐清目標人群，再創造「係我」的具體痛點 |
| **第二層：故事中段** | 「我能代入嗎？有畫面嗎？」 | 少形容詞，多動詞；少概括，多具體事件 |
| **第三層：轉折+結尾** | 「為什麼有效？我能信嗎？」 | 冤枉路 + 危機感 + 機制解釋 = 完整可信度鏈 |

### 老師診斷的四個問題與底層邏輯

**問題一：Hook 未關觀眾事**

底層邏輯：Hook 的功能不是「介紹你自己」，而是「讓觀眾看到自己的問題」。

老師的三步公式：
1. 釐清目標人群（「呢條片係俾邊啲人睇？」）
2. 創造「係我」的具體痛點（「佢哋日日經歷、一聽就係我嘅具體畫面」）
3. 預示具體有畫面的未來結果（「你用咗咩方法、達成咗一個點樣嘅更好未來」）

**問題二：故事中段用概括，不用畫面**

底層邏輯：「概括」是你腦中的分類，「畫面」是觀眾腦中的電影。觀眾不會對分類有感情，只會對電影有感情。

老師的改寫原則：
- ❌ 概括：「我天生扁平足，仲有拇趾外翻」（分類，觀眾腦中沒有畫面）
- ✅ 事件：「有日返工，一個同事望住我，問：『你做咩行路拐吓拐吓？』」（時間+地點+人物+對白+畫面）

公式：**特定時間 + 特定地點 + 特定事件 + 人物/對白**

**問題三：轉折位太快太順，缺乏冤枉路**

底層邏輯：「直到我墊咗個嘢」這句話太順，觀眾沒有理由相信。觀眾相信的是「這個人試過我試過的方法，都沒用，然後才找到這個」。

老師的轉折三要素：
1. 你行過幾多冤枉路？（觀眾也犯過的錯誤）
2. 問題不解決，將來會惡化到什麼程度？（危機感）
3. 你怎麼遇到轉折點？（過程本身就是故事）

**問題四：結尾缺少「點解有效」的機制解釋**

底層邏輯：觀眾看到「Before → After」，但不知道「為什麼」，就不會相信。機制解釋 = 「原來係咁，所以先得」的頓悟感。

老師的公式：Before（你試過的錯方法）→ 轉折（找到真正有效的方法）→ **機制解釋（為什麼有效）** → After（你現在的狀態）

## 三、觀眾視角設計原則（七條鐵律）

### 鐵律 1：Hook 三問前置檢查

在寫任何一句 Hook 之前，必須先回答三個問題：

```
Q1：這條片是給哪些人看的？（具體到職業/症狀/生活場景）
Q2：這群人日日都在經歷什麼痛苦？（具體到一個他們「一聽就係我」的畫面）
Q3：我能給他們一個怎樣具體有畫面的未來結果？（不是「好返」，是「可以做到什麼事」）
```

**快速診斷：** 如果你的 Hook 沒有回答 Q2（觀眾的具體痛苦），就是「你的角度」，不是「觀眾的角度」。

---

### 鐵律 2：「概括」vs「畫面」的轉換公式

每次寫「概括句」時，必須用以下公式轉換成「畫面句」：

```
概括句 → 問自己「這件事是什麼時候、在哪裡、怎麼發生的？」
→ 加入：時間 + 地點 + 人物 + 動作/對白
→ 輸出：畫面句
```

**例子：**
| 概括句（❌） | 畫面句（✅） |
|------------|------------|
| 「我天生扁平足，仲有拇趾外翻」 | 「有日返工，一個同事望住我，問：『你做咩行路拐吓拐吓？』」 |
| 「份工成日要企、行街、跳完舞」 | 「跳完一堂舞，坐低除鞋嗰刻，腳板痛到我唔敢再踩落地」 |
| 「年紀愈大痛得愈犀利」 | 「上個月，我第一次諗過係咪要放棄跳舞——唔係唔想，係真係痛到做唔到」 |
| 「我試過自己做動作去改善」 | 「我知道有動作可以改善，我有做啊，但有時偷懶冇做，又打回原形」 |

---

### 鐵律 3：冤枉路必須是「觀眾也犯過的錯」

冤枉路的設計原則：**你講你的錯，其實係喺度提醒觀眾「唔好再行我行過嘅錯路」。**

冤枉路的三個層次（由弱到強）：
1. **弱版**：「我試過換鞋，冇用」（只有你的行為，沒有觀眾的共鳴）
2. **中版**：「我換過好多款鞋，貴嘅平嘅都試晒，對腳一樣痛」（有細節，觀眾能代入）
3. **強版**：「連我自己，都解決唔到自己對腳——我係教體態動作㗎，我知道有動作可以改善，但問題根本仲喺度」（專家也搞不定自己 = 問題真的很難 = 信任感最強）

**鐵律：** 冤枉路必須包含「觀眾也會犯的錯」，不能只有你自己的錯。

---

### 鐵律 4：危機升級必須用「主觀恐懼」語言

危機升級不是客觀描述（「腳痛會惡化」），而是主觀恐懼（「我開始驚——係咪之後連行街都要忍住痛過日子？」）。

**公式：**
```
「我開始驚——係咪之後 [最壞的情況]？」
```

**例子：**
- ✅「我開始驚——係咪之後連行街、行樓梯都要忍住痛過日子？」
- ✅「我開始諗——係咪我要就咁放棄跳舞，再都唔會跳？」
- ❌「腳痛如果唔處理，會越來越嚴重」（客觀描述，沒有情緒）

---

### 鐵律 5：轉折必須用「誠實的低期望」開場

轉折的最可信版本不是「我找到了！」，而是「我其實沒有期望，但這次真的不同」。

**公式：**
```
「老實講我冇乜期望——因為 [你試過的方法都沒用]。
但呢次真係唔同。[第一步就不同的即時感受]。」
```

**禁忌：**
- ❌「我試咗一款鞋墊，真係好好用！」（太順，不可信）
- ❌「有廠家搵我試，我即刻知道呢個係真正有效嘅」（沒有低期望，沒有轉折張力）

---

### 鐵律 6：機制解釋必須用「身體感受」語言，不用技術術語

機制解釋的目的是讓觀眾「原來係咁，所以先得」的頓悟感。

**公式：**
```
「點解有效？因為 [身體感受描述，不是技術參數]。
我試咗 [時間框架]，[具體改善]。
而且 [連帶效果]——因為 [你的 IP 主線邏輯]。」
```

**例子：**
- ✅「點解有效？因為佢托返起我塌咗嘅足弓，我踩落地個衝擊力唔再全部壓落腳板。」
- ❌「點解有效？因為佢有 AI 分析技術，配合物理治療師研發。」（技術術語，觀眾沒有感受）

---

### 鐵律 7：每一句話的「觀眾視角」自我檢查

在完成口播稿後，對每一句話問：

```
「如果我是觀眾，我會問『關我咩事？』嗎？」
```

如果答案是「會」，這句話需要改寫。

**四個常見「自我角度」陷阱：**
1. 「我天生扁平足」→ 觀眾：「關我咩事？」（改為：「你有冇試過...」）
2. 「我做咗件事令我重拾興趣」→ 觀眾：「你係邊個？」（改為：先建立觀眾的痛點）
3. 「直到我墊咗個嘢」→ 觀眾：「你點知有效？」（改為：加入冤枉路 + 低期望）
4. 「真係冇咗以前嗰種痛」→ 觀眾：「點解有效？」（改為：加入機制解釋）

## 四、觀眾視角 vs 自我角度的完整對比

| 段落 | 自我角度（❌） | 觀眾視角（✅） |
|------|-------------|-------------|
| Hook | 「我重拾返一個放棄咗好耐嘅興趣」 | 「你有冇試過——企足一日，收工返到屋企，對腳好似拖住兩嚿鉛？」 |
| 痛點根源 | 「我天生扁平足，仲有拇趾外翻」 | 「有日返工，一個同事問：『你做咩行路拐吓拐吓？』」 |
| 冤枉路 | 「我試過自己做動作去改善，有用，但斷唔晒尾」 | 「我換過好多款鞋，貴嘅平嘅都試晒。我自己係教體態動作㗎，但連我自己都解決唔到自己對腳。」 |
| 危機升級 | 「年紀愈大痛得愈犀利，最後我唯有放棄咗跳舞」 | 「我開始驚——係咪之後連行街、行樓梯都要忍住痛過日子？」 |
| 轉折 | 「直到我墊咗一個嘢喺鞋度」 | 「老實講我冇乜期望——坊間大牌子我都試過。但呢次真係唔同。」 |
| 機制解釋 | （缺失） | 「點解有效？因為佢托返起我塌咗嘅足弓，踩落地唔再係硬撐。」 |
| 結尾 | 「你對腳撐咗你咁多年，係時候有樣嘢撐返佢」 | 保留（這句已經是觀眾視角 ✅） |

## 六、快速診斷清單（出片前必查）

```
□ Hook 有沒有先回答「關觀眾咩事」？（三問前置檢查）
□ 故事中段有沒有「概括句」需要轉換成「畫面句」？
□ 冤枉路有沒有包含「觀眾也犯過的錯」？
□ 危機升級有沒有用「主觀恐懼」語言（「我開始驚」）？
□ 轉折有沒有用「誠實的低期望」開場？
□ 結尾有沒有「機制解釋」（點解有效）？
□ 每一句話通過「關我咩事？」自我檢查？
```

## 七、觸發條件

**必須參閱本框架的情況：**
- 當 Cathy 提交故事型口播稿（特別是商業合作片）要求診斷時
- 當口播稿被診斷為「用自己角度講故」時
- 當口播稿缺少冤枉路、危機升級或機制解釋時
- 當 Hook 被診斷為「未關觀眾事」時
- 當口播稿有「概括句」需要轉換成「畫面句」時

**與 `story_reel_structure.md` 的分工：**
- `story_reel_structure.md`：提供十段落結構和每段落的設計原則（What to include）
- 本框架：提供每段落的「觀眾視角」轉換公式（How to make it audience-first）
