# Hook 動作邏輯緊密性 + 測試→解決閉環框架
**版本：** 1.0 | **建立日期：** 2026-07-09 | **觸發來源：** 拗柴口播稿第三方 AI 診斷分析

---

## 一、這個框架解決什麼問題

現有框架（`viral_replication_system.md` 六格公式）已定義了「④ 即刻畀動作」格的重要性，但缺少以下兩個維度：

1. **Hook 動作的「邏輯緊密性」診斷**：Hook 動作必須直接測試問題的核心成因，而不是相關症狀。「做唔到 Heel Raise = 易拗柴」這個推論不夠 tight，觀眾潛意識會覺得「唔係喎」。

2. **「測試 → 解決」的完整閉環**：Hook（測試）和訓練動作（解決）必須形成因果關係，需要橋接句連接。否則觀眾會覺得「兩個動作各講各」，脫節感削弱信任。

---

## 二、Hook 動作邏輯緊密性

### 2.1 定義

**邏輯緊密性** = Hook 動作所直接測試的能力，與問題核心成因的因果關係強度。

```
高邏輯緊密性（✅）：
Hook 動作 → 直接暴露問題的核心成因

低邏輯緊密性（❌）：
Hook 動作 → 只暴露問題的相關症狀（但不是直接成因）
```

### 2.2 案例分析：拗柴選題

| Hook 動作 | 直接測試的能力 | 與「拗柴」的關係 | 邏輯緊密性 |
|---------|------------|--------------|----------|
| **單腳站** | 平衡 + 本體感覺 | 直接症狀：拗柴的人單腳站一定搖 | ✅ 高 |
| Heel Raise | 小腿力量 | 相關但不直接：小腿弱不一定易拗柴 | ❌ 低 |
| 腳趾抓毛巾 | 腳趾靈活性 | 間接相關：足弓強化的一部分 | ❌ 低 |

**為什麼「Heel Raise ≠ 拗柴」：**
- 一個人小腿強但足弓塌，一樣會拗柴
- 一個人小腿弱但足弓穩，不一定會拗柴
- 推論「做唔到 Heel Raise → 易拗柴」在臨床上不成立

**為什麼「單腳站 = 拗柴」：**
- 拗柴的核心是「平衡 + 本體感覺不足」
- 單腳站直接測試平衡 + 本體感覺
- 推論「單腳站搖晃 → 平衡不穩 → 易拗柴」成立 ✅

### 2.3 邏輯緊密性三層檢查

**第一層：問題的核心成因是什麼？**
- 拗柴 → 核心成因：平衡不穩（足弓塌導致踝關節鬆）
- 足底筋膜炎 → 核心成因：足底筋膜過度拉伸（足弓支撐不足）
- 膝頭痛 → 核心成因：股四頭肌弱（膝關節穩定性不足）

**第二層：Hook 動作直接測試的是什麼？**
- 單腳站 → 直接測試：平衡 + 本體感覺
- Heel Raise → 直接測試：小腿力量
- 腳趾抓筆 → 直接測試：腳趾靈活性 + 足底肌肉控制

**第三層：兩者是否直接因果？**
- 「平衡不穩」是「易拗柴」的直接成因 → 單腳站 ✅
- 「小腿力量弱」不是「易拗柴」的直接成因 → Heel Raise ❌

### 2.4 常見選題的高邏輯緊密性 Hook 動作

| 選題 | 核心成因 | 高邏輯緊密性 Hook 動作 |
|------|---------|---------------------|
| 拗柴 | 平衡不穩 | **單腳站 10 秒**（搖晃 = 直接暴露問題）|
| 足底筋膜炎 | 足弓支撐不足 | **腳趾公抬起測試**（足弓能否撐起 = 直接暴露問題）|
| 拇趾外翻 | 足弓塌 + 腳趾公外偏 | **腳趾公能否向內回正**（直接暴露問題）|
| 膝頭痛 | 股四頭肌弱 | **5 秒深蹲測試**（膝頭有否抖動 = 直接暴露問題）|
| 腰痛 | 核心肌群弱 | **貓牛式腰部活動度測試**（直接暴露問題）|

### 2.5 診斷問題：「呢個 Hook 動作夠 tight 嗎？」

**快速診斷公式：**
```
問：「做唔到呢個動作，一定代表有呢個問題嗎？」
答案是「唔一定」→ 邏輯緊密性低 ❌
答案是「係，直接代表」→ 邏輯緊密性高 ✅
```

**例子：**
- 「做唔到 Heel Raise，一定代表易拗柴嗎？」→ 唔一定（可能只係小腿弱）❌
- 「單腳站搖晃，一定代表易拗柴嗎？」→ 係，直接代表平衡不穩 ✅

## 三、「測試 → 解決」完整閉環

### 3.1 定義

**完整閉環** = Hook 測試（發現問題）+ 橋接句（連接）+ 訓練動作（解決問題）

Reels 不是「教一個動作」，而是「解決一個問題」。Hook 和訓練動作必須形成因果關係，讓觀眾感受到「我發現了問題，然後你教我解決」的完整故事線。

### 3.2 閉環結構

```
Hook 測試（0-3s）
「單腳企 10 秒——你個腳踝係咪左搖右擺企唔穩？」
    ↓ 發現問題
場景共鳴 + 推翻常識 + 原理解釋 + 惡化層（3-30s）
    ↓ 理解問題
橋接句（30s）
「所以頭先叫你試嗰個平衡——而家教你點樣練返個穩。」
    ↓ 連接
訓練動作（30-44s）
「扶住牆，慢慢將腳跟提起…做 15 下。」
    ↓ 解決問題
效果承諾（44-49s）
「三個禮拜之後，踩到唔平嘅地唔再即刻歪。」
```

### 3.3 橋接句的寫法公式

**公式：**
```
「所以頭先叫你試嗰個 [Hook 測試的能力]——而家教你點樣練返個 [訓練動作的目標]。」
```

**例子：**
- 拗柴：「所以頭先叫你試嗰個平衡——而家教你點樣練返個穩。」
- 足底筋膜炎：「所以頭先叫你試嗰個足弓支撐力——而家教你點樣強化呢個底座。」
- 膝頭痛：「所以頭先叫你試嗰個膝頭穩定性——而家教你點樣練返個支撐。」

### 3.4 Hook 動作 vs 訓練動作的分工

**關鍵原則：**
- **Hook 動作** = 測試問題（暴露問題的直接症狀）
- **訓練動作** = 解決問題（針對問題的核心成因）
- 兩個動作**不需要相同**，但必須有因果關係

**拗柴案例：**
| 動作 | 角色 | 目的 |
|------|------|------|
| 單腳站 | Hook 測試 | 暴露「平衡不穩」的直接症狀 |
| Heel Raise | 訓練動作 | 強化足弓支撐 + 踝關節控制（解決問題的核心成因）|

**為什麼這樣分工更好：**
- 單腳站：觀眾即刻感受到「我企唔穩，我有問題」
- Heel Raise：觀眾學到「呢個動作係練足弓，解決我企唔穩的問題」
- 橋接句把兩者連起來：「頭先測到你平衡不穩，而家教你練足弓穩返」

### 3.5 「測試 → 解決」閉環檢查清單

- [ ] **Hook 動作的邏輯緊密性**：Hook 動作是否直接測試問題的核心成因？
- [ ] **Hook 動作的可感知性**：觀眾做完 Hook 動作，能否即刻感受到「我有問題」？
- [ ] **橋接句**：是否有橋接句連接 Hook 測試和訓練動作？
- [ ] **訓練動作的針對性**：訓練動作是否針對問題的核心成因？
- [ ] **閉環感**：觀眾看完整條片，是否感受到「我發現了問題，然後你教我解決」？

## 五、白話翻譯原則（附加）

另一個 AI 的診斷中發現，Cathy 的口播稿有「專業詞未翻譯」的問題。

**常見需要翻譯的專業詞：**

| 專業詞 | 白話翻譯 | 翻譯原則 |
|--------|---------|---------|
| 代償 | 「幫手頂住呢個唔穩」/ 「被迫幫手做工」 | 用「動作」描述，讓觀眾感受到「負擔感」 |
| 本體感覺 | 「你隻腳感受唔到自己喺邊」 | 用「感受」描述，讓觀眾能代入 |
| 足底筋膜 | 「腳板底嗰條筋」 | 用「位置 + 形狀」描述 |
| 股四頭肌 | 「大腿前面嗰塊肌肉」 | 用「位置」描述 |
| 搖搖欲墜 | 「一直喺度輕微咁搖緊」 | 口語化，讀落更順 |

**翻譯原則：**
1. 用「動作」描述抽象機制（「幫手頂住」比「代償」更有畫面感）
2. 用「位置」描述解剖結構（「腳板底嗰條筋」比「足底筋膜」更直接）
3. 用「感受」描述感覺（「你隻腳感受唔到自己喺邊」比「本體感覺不足」更能代入）
