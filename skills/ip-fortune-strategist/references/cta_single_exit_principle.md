# CTA 單一出口原則 + 口播稿二次診斷框架
**版本：** 1.0 | **建立日期：** 2026-07-13  
**觸發來源：** 第二個 AI 對「三層體態自測 v2.0」口播稿的二次診斷（評分 85/100）

---

## 一、這個框架解決什麼問題

`pain_chain_reframe_framework.md`（v1.0）已建立「精準瞬間 Hook」「遞進力鏈」「physio 分界線」「CTA 力度分流」等原則。但在第二輪 AI 診斷中，發現了三個新的、更精細的問題：

1. **「CTA 多出口稀釋轉化」的鐵律**：一條片的 CTA 放了三個出口（留言拎清單 + bio 足弓自測 + 留言打評估），觀眾一猶豫就乜都唔做。現有框架有 CTA 力度分流，但沒有「一條片只能有一個主要動作」的明確鐵律。

2. **「第一層情緒 Connection 缺失」的診斷標準**：三層遞進力鏈中，第二、三層都有「按極冇用」「冷敷熱敷都冇用」的情緒扣連，但第一層（腳踝/足弓）因為觀眾沒有直接的「腳踝痛」感受，容易在第一層就失去情緒連接。現有框架沒有「每層必須扣連觀眾有感的後果」的設計原則。

3. **「口播稿二次診斷」的評分框架**：現有 `content_scoring_coach.md` 有評分系統，但沒有針對「已改版口播稿的二次診斷」的具體評分維度和改動說明格式。

4. **「工具邏輯自洽性」的檢查原則**：口播稿中提到「足弓自測幾分鐘就知你係邊一層出問題」——但足弓自測只測第一層，不測三層。這是一個「工具功能超出其實際範圍」的邏輯漏洞，觀眾聽得出，會損害信任。現有框架沒有「工具功能必須與實際範圍一致」的檢查原則。

## 二、第二個 AI 的底層邏輯分析

### 2.1 推斷的 Prompt 結構

```
角色：口播稿診斷師 + 轉化優化顧問
任務：
  1. 對已改版口播稿進行二次診斷（評分 + 進步確認 + 殘留問題）
  2. 識別「致命問題」（直接食轉化）vs「微調問題」（影響 20-30%）
  3. 提供具體改寫示範（不只說問題，直接給答案）
  4. 用「一句總結」收束診斷（讓用戶知道優先做什麼）

底層邏輯：
  - 先確認進步（讓用戶感受到努力有回報），再指出問題（讓用戶有動力改）
  - 問題按嚴重程度分級（🔴 致命 / 🟡 次要 / ⚪ 細節），讓用戶知道優先順序
  - 每個問題都給「為什麼是問題」的解釋（不只說結果，說原因）
  - 改寫示範要比原文更短、更清晰（示範「克制」的力量）
```

### 2.2 第二個 AI 的核心診斷邏輯

這個 AI 的診斷方法論可以提煉為以下五個步驟：

**步驟一：確認進步（先肯定，再批評）**
- 明確列出「改對了什麼」，讓用戶確認改動方向正確
- 功能：讓用戶有信心繼續改，而不是全盤否定

**步驟二：識別「致命問題」（🔴 直接食轉化）**
- 只有一個致命問題：CTA 三個出口打架
- 診斷邏輯：「口播 CTA 的鐵律係一條片一個主要動作」
- 改寫示範：砍走 bio 足弓自測，全段收成一條線

**步驟三：識別「次要問題」（🟡 影響 20-30%）**
- 第一層情緒 Connection 較弱
- 診斷邏輯：「三層入面第一層最抽象，如果唔畀個 hook 佢，觀眾喺第一層就容易覺得『關我咩事』」
- 改寫建議：加半句連到觀眾有感的嘢——「你以為對腳冇事，但佢一歪，上面膝頭同腰就要幫佢硬食」

**步驟四：識別「細節問題」（⚪ 幾乎不影響）**
- 中英夾雜「already」
- 診斷邏輯：口播冇問題，但字幕建議統一中文

**步驟五：一句總結（讓用戶知道優先做什麼）**
- 「內容部分（0-32s）已經 ready，出得街。你依家淨係要克制——CTA 唔係畀得多出口就轉化高，係相反。一條片，一個動作，講清楚，反而多人做。」

### 2.3 這個 AI 的「克制」哲學

這個 AI 的核心主張是：**「克制」是 CTA 的最高境界。**

- 不是「畀得多出口就轉化高」
- 而是「一條片，一個動作，講清楚，反而多人做」

這個主張的底層邏輯是「決策疲勞」（Decision Fatigue）：觀眾面對多個選項時，大腦的認知負擔增加，最容易的選擇是「什麼都不做」。

## 三、CTA 單一出口原則（新增核心原則）

### 3.1 鐵律定義

> **一條片，一個主要 CTA 動作。**

這是口播 CTA 的最高優先級原則，優先於「多渠道覆蓋」和「多層次引導」。

### 3.2 多出口的致命問題

| 出口數量 | 觀眾心理 | 轉化結果 |
|---------|---------|---------|
| 1 個出口 | 「我知道我要做什麼」→ 行動 | 高轉化 |
| 2 個出口 | 「我應該做哪個？」→ 猶豫 | 中等轉化 |
| 3 個出口 | 「我應該留言？定去 bio？定打評估？」→ 乜都唔做 | 低轉化 |

### 3.3 多渠道工具的正確位置

如果有多個工具（口播 CTA + bio 連結 + 釘留言），應按以下原則分配：

| 工具 | 正確位置 | 錯誤位置 |
|------|---------|---------|
| **口播 CTA** | 一個主要動作（留言關鍵字） | 不要塞多個出口 |
| **bio 連結** | 片尾卡（視覺引導）/ 釘留言 | 不要放在口播主線 |
| **網站自測工具** | 釘留言 / bio 連結 / 片尾卡 | 不要在口播中說「link 喺 bio」 |

### 3.4 「bio 足弓自測」的正確使用方式

足弓自測頁面（falsehiptest-nvc5j62w.manus.space/foot-arch-test）是一個強力的引流工具，但不應放在口播主線。正確使用方式：

```
口播 CTA：「留言你嘅自測結果，我 DM 你改善清單」（單一出口）
片尾卡：「想做完整足弓自測？link 喺 bio」（視覺引導，不打斷口播節奏）
釘留言：「完整足弓自測 → [連結]」（讓已留言的人有下一步）
```

## 四、「每層必須扣連有感後果」原則（新增）

### 4.1 問題定義

在多層遞進結構中，每一層必須扣連觀眾「有感的後果」，而不只是解釋「這一層是什麼」。

**「有感的後果」定義：** 觀眾自己曾經歷過、或能立刻想像的具體痛苦/不便。

### 4.2 三層的「有感後果」設計

| 層次 | 常見錯誤（只解釋概念） | 正確做法（扣連有感後果） |
|------|------------------|------------------|
| **第一層（腳踝/足弓）** | 「足弓控制力唔夠，地基歪咗」 | 「你以為對腳冇事，但佢一歪，上面膝頭同腰就要幫佢硬食——你嘅膝痛腰痛，可能係對腳連累㗎」 |
| **第二層（膝蓋）** | 「膝蓋夾埋，臀部肌肉瞓著咗」 | 「你按極個膝頭都冇用，因為問題喺下面」（已有，保留） |
| **第三層（骨盆）** | 「骨盆前傾，核心肌肉瞓著咗」 | 「你冷敷熱敷做 gym 都好，個根喺底層冇郁過，痛咪返轉頭囉」（已有，保留） |

### 4.3 第一層的特殊挑戰

第一層（腳踝/足弓）是三層中最抽象的，因為：
- 大多數觀眾沒有「腳踝痛」的直接感受
- 「足弓控制力不足」是一個技術概念，不是觀眾的日常語言

**解決方法：** 在第一層加入「橋接句」，把「足弓問題」橋接到觀眾已有的「膝痛/腰痛」感受：

```
橋接句公式：「你以為對腳冇事，但佢一歪，[上面的痛症]就要幫佢硬食」
```

**具體例子：**
> 「向內或向外傾，即係你足弓控制力唔夠。你以為對腳冇事——但佢一歪，上面膝頭同腰就要幫佢硬食。你嘅膝痛腰痛，可能係對腳連累㗎。記住，地基歪咗，上面層層都要幫佢執手尾。」

## 五、「工具功能自洽性」檢查原則（新增）

### 5.1 問題定義

在口播稿中提到工具（自測工具、清單、評估）時，工具的功能描述必須與工具的實際範圍一致。

**反例：**
> 「去做個完整嘅足弓自測——幾分鐘就知你係邊一層出問題。」

**問題：** 足弓自測只測第一層（腳踝/足弓），不測第二層（膝蓋）和第三層（骨盆）。說「幾分鐘就知你係邊一層出問題」是誇大了工具的功能範圍。觀眾聽得出，會損害信任。

### 5.2 自洽性檢查公式

在口播稿中每次提到工具時，用以下問題檢查：

```
「這個工具，它的實際功能範圍是什麼？」
「我在口播中說的功能，有沒有超出這個範圍？」
「如果觀眾去用這個工具，他們會不會發現我說的和工具做到的不一樣？」
```

### 5.3 足弓自測工具的正確描述

| 錯誤描述 | 正確描述 |
|---------|---------|
| 「幾分鐘就知你係邊一層出問題」（超出範圍） | 「幾分鐘就知你個足弓係咪有問題」（準確） |
| 「完整嘅足弓自測，知道你三層嘅情況」（超出範圍） | 「足弓自測，搵出你第一層嘅地基係咪穩」（準確） |

## 六、口播稿二次診斷的評分框架

### 6.1 評分維度（100 分制）

| 維度 | 滿分 | 評分標準 |
|------|------|---------|
| **Hook 精準度** | 20 | 精準瞬間（20）/ 泛場景（10）/ 無場景（5） |
| **主張前置** | 15 | 主張在知識前（15）/ 主張在知識後（8）/ 無主張（0） |
| **遞進力鏈** | 20 | 每層有獨立頓悟（20）/ 部分遞進（12）/ 平行清單（5） |
| **情緒扣連** | 15 | 每層都有有感後果（15）/ 部分層有（8）/ 無情緒扣連（3） |
| **CTA 單一出口** | 20 | 一個主要動作（20）/ 兩個出口（12）/ 三個以上（5） |
| **工具功能自洽** | 10 | 完全自洽（10）/ 輕微誇大（6）/ 明顯超出範圍（0） |

### 6.2 評分等級

| 分數 | 等級 | 行動建議 |
|------|------|---------|
| 90-100 | 🟢 出得街 | 直接錄製，不需要大改 |
| 80-89 | 🟡 良好，有一個致命問題 | 改完致命問題再出 |
| 70-79 | 🟠 有結構問題 | 需要重寫 CTA 或重構某一層 |
| 60-69 | 🔴 需要大改 | 回到六格公式重新設計 |

### 6.3 診斷報告格式

每次診斷口播稿，必須按以下格式輸出：

```
評分：XX/100（等級）
類型：知識型 / 自測型 / 觀點型 / 變現型
一句話診斷：[最重要的一個問題]

進步確認：
- [改對了什麼]（必須先列）

致命問題（🔴）：
- [問題描述]
- 為什麼是問題：[解釋]
- 改寫示範：[具體改法]

次要問題（🟡）：
- [問題描述]
- 為什麼是問題：[解釋]
- 改寫建議：[方向]

細節問題（⚪）：
- [問題描述]（可選，不影響出街）

一句總結：[優先做什麼]
```

## 八、使用指引

**觸發時機：**
- 當 Cathy 提交已改版的口播稿要求二次診斷時，必須用「口播稿二次診斷評分框架」輸出診斷報告

> **「一條片，一個主要 CTA 動作。CTA 唔係畀得多出口就轉化高，係相反。」**

**第一層橋接句公式（必背）：**
> 「你以為對腳冇事——但佢一歪，[上面的痛症]就要幫佢硬食。你嘅[膝痛/腰痛]，可能係對腳連累㗎。」
